# TrafficGraph 智慧城市答辩讲稿

## 建议时长

- 标准答辩：6 至 8 分钟
- 快速展示：3 至 4 分钟
- 演示视频：约 3 分 19 秒

## 一、开场

各位评委老师好，我们的项目是 TrafficGraph，上海市智慧交通指挥 Agent。

当前交通指挥系统并不缺少数据，真正的问题是数据分散、研判链路长、专业知识
和实时状态之间缺少连接。值班人员往往需要同时看多个系统，再凭经验完成判断。

我们的目标不是替代指挥人员，而是把实时交通数据、专业知识、信号优化、事件处置
和报表输出统一到一个可以对话、可以解释、可以追溯的中控平台中。

## 二、问题分析

我们重点解决三个问题。

第一，数据分散。路网、信号、事件、警情和视频分布在不同的系统里，查询成本高。

第二，研判依赖经验。传统监控只能看到拥堵结果，无法快速关联饱和度、排队、
配时和事件影响。

第三，报告制作链路长。值班人员发现问题后，还需要人工整理数据、制作表格、
形成报表。

TrafficGraph 将这三段链路整合到同一个 Agent 中，形成从问题、数据、分析、
建议到报告的完整闭环。

## 三、系统架构

系统采用五层结构。

最上层是智慧交通指挥 Web 控制台。

第二层是 Agent 决策层，由 LangGraph 负责状态流转、认知解析、工具调度和报告生成。

第三层是业务 Skill 层，包括交通专家、信号调度和 UI Router。

第四层是工具与数据层，包含十二个交通数据工具和 TrafficSim 确定性仿真引擎。

最底层是知识基础设施，包括 ChromaDB 交通知识库、长期记忆和操作审计。

后端使用 FastAPI、Pydantic、LangGraph 和 Uvicorn，前端使用原生 HTML、CSS、
JavaScript 和 SVG，保证部署轻量且现场稳定。

## 四、Agent 工作流程

用户输入自然语言后，系统会完成五个步骤。

第一步，认知解析，判断用户问的是实时数据、专业知识、页面查看还是报表导出。

第二步，选择工具。Agent 会从十二个交通数据工具中选择最少且足够的工具。

第三步，执行工具，获取全市态势、路口状态、干线绿波、信号配时或事件数据。

第四步，技能编排。交通专家和信号调度 Skill 会补充知识来源、拒答规则和安全约束。

第五步，生成报告。系统输出结论、数据依据和建议，并将页面动作转为人工确认按钮。

## 五、现场演示

### 态势总览

进入系统后，左侧是四个固定工作视图，中间是业务工作区，右侧是 Agent Copilot。

态势总览中可以同时看到城市拥堵指数、平均车速、活跃事件、Top5 路口和实时路网。
每个路口节点使用不同颜色表示饱和度，点击后可以快速定位异常。

### 路网监控

切换到路网监控，可以搜索路口或按干线筛选。

表格展示服务水平、饱和度、延误、排队和当前相位。

选择路口后，右侧会显示进口道运行状态，帮助定位具体瓶颈。

### 信号控制

信号控制页展示五条干线的绿波状态和带宽。

选择具体路口后，可以看到周期、相位差、协调组和各相位绿灯时间。

系统基于 Webster 计算给出优化建议，但所有建议都必须满足最小绿灯、行人过街、
黄灯清空和协调同步约束。

### 事件处置

事件处置页统一展示事故、车辆抛锚、道路施工和临时管制。

页面包含事件严重度、占道情况、预计恢复时间、处置资源和调度时间线，
便于值班人员快速确定处置优先级。

### 数据可视化报表

点击导出当前视图，系统会生成报告抽屉。

报告同时包含数据表格、柱状图、折线图、环形图和 CSV 文件。

例如态势总览可以导出拥堵 Top5，信号控制可以导出相位和绿灯时间，
事件页面可以导出事件明细和严重度分布。

### Agent Copilot

右侧 Copilot 可以直接使用自然语言提问。

例如询问现在上海市哪里最堵，系统会自动调用全市态势工具，展示工具调用过程，
并生成分析报告。

Agent 不会自动切换页面，所有页面动作都需要人工确认。

## 六、技术亮点

第一，工具契约统一。十二个交通数据工具全部使用 Pydantic 强类型模型，
错误统一返回，不依赖随机假数据。

第二，确定性仿真。相同日期、对象和数据类型产生一致结果，适合现场演示和回归测试。

第三，知识与数据融合。实时交通工具负责回答现在发生了什么，
交通知识库负责解释为什么以及应该遵循什么规范。

第四，一屏式中控台。四个视图点击切换，右侧 Agent 独立滚动，
不会因为对话带动整个页面跳转。

第五，自动报表输出。同一份数据可以同时生成表格、图表和 CSV。

第六，安全可控。Agent 只分析和建议，不直接控制真实信号，不自动执行管制。

## 七、总结

TrafficGraph 将交通数据、专业知识、信号分析和事件调度统一到一个 Agent 中，
实现了从自然语言查询到可视化研判和报表输出的完整闭环。

项目坚持可复现、可解释、可扩展和安全可控，既能用于比赛展示，
也可以接入真实交通 API 和信号系统继续演进。

## 八、常见问答

### 为什么不用纯大模型直接回答？

实时交通状态和规范条文不能依赖模型记忆。实时数据必须来自工具，
专业知识必须来自 RAG，模型只负责意图理解和结果解释。

### 如果真实接口不可用怎么办？

系统提供 TrafficSim 确定性仿真。真实接口接入时只需要替换工具适配器，
Agent、Skill、Prompt 和前端无需改动。

### Agent 会不会直接调整信号？

不会。Agent 只给出建议。配时编辑、应急接管和强制诱导都属于受限操作，
必须由授权人员审批。

### 交通知识库准确吗？

知识库采用 RAG 检索并保留来源片段。低置信度时系统拒答，
不允许模型用通用知识补造规范或实时状态。

### 系统的可扩展性如何？

新增交通数据工具时，只需要实现工具、注册 Schema、补充路由和测试。
新增知识类型时，只需要扩充 JSONL 语料并重新入库。

### 为什么做成中控台而不是普通聊天页面？

交通指挥需要同时观察态势、事件、信号和资源状态。普通聊天页面无法满足
值班人员对信息密度、固定导航和快速切换的要求，因此我们采用一屏式中控布局。
